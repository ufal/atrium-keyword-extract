## Issue Digest: #11 - NameTag3 Multilingual Base

> 🔀 **Not this repository's issue:** [ufal/atrium-nlp-enrich#11](https://github.com/ufal/atrium-nlp-enrich/issues/11) stays in nlp-enrich, whose copy of this log is the maintained one; this copy came with the history on 2026-10-01.

* **Issue Title:** NameTag3 multilingual base instead of per-language choice of NER models.


* **Labels:** `enhancement`, `development`.


* **Core Objective:** Replace the existing per-language NameTag3 NER models with a generalized, multilingual model alternative.


**Progress Timeline:**

* **Initialization:** The issue was opened to shift towards a multilingual model, referencing previous context from Issue #7.


* **Upstream Blocker:** The implementation was initially paused because the required multilingual model was not yet available in the NameTag3 API.


* **Resolution:** A request was made to update the API model list (nametag3 issue #4) and was successfully resolved, exposing several new models, including `nametag3-multilingual-onto-260521` and `nametag3-multilingual-conll-260521`.


* **Testing:** The new models were successfully tested on synthetic data samples.


* **Data Mapping:** Testing revealed a necessary tagset mapping from CNEC to ONTO.


* **Implementation:** The configuration was updated to use the `nametag3-multilingual-onto-260521` model, and `CNEC_TO_ONTO_MAP` logic was added to the summarization utility to seamlessly handle tagset translation.
* **Verification:** A unit test suite (`TestNameTagExplanationMapping`) was created and calibrated to ensure that both native ONTO strings and legacy CNEC mappings resolve correctly.
* **Current Status:** Fully implemented and verified. The codebase successfully utilizes the generalized multilingual model.

* **Cross-reference (added 2026-09-24):** the side-by-side evidence for this switch is [#19](https://github.com/ufal/atrium-nlp-enrich/issues/19)'s `NER_onto_VS_cnec.zip` (2026-07-20): the same 16 documents through `nametag3-czech-cnec2.0-240830` and `nametag3-multilingual-onto-260521`. It was delivered three weeks after this issue closed, so it documents the choice rather than having driven it; the same 16 reports later became the evidence corpus of #6 Phase 9. `CNEC_TO_ONTO_MAP` is still in `api_util/summarize_nt_udp.py` (the summary CSV's explanations). TEITOK format 2 (v0.21.0) takes its coarse types from `api_util/ner_types.py` (`CNEC_TO_CONLL`, `ONTO_TO_CONLL`) and keeps the raw label in `@onto` or `@cnec`, so OntoNotes entities are no longer written as `MISC`.
