# [\#1 Issue](https://github.com/ufal/atrium-keyword-extract/issues/1) `open`: Separate keyword extraction workflows into another repo
**Labels**: `documentation`, `enhancement`, `development`


#### <img src="https://avatars.githubusercontent.com/u/65828620?u=80b39d3cb2967c52e1d4af28dcefc7a1efdfdc79&v=4" width="50">[K4TEL](https://github.com/K4TEL) opened issue at [2026-09-30 13:50](https://github.com/ufal/atrium-keyword-extract/issues/1):

Both statistical keyword extraction with KER or KeyBERT, and the LLM-based controlled vocabulary terms extraction must be separated into another repo `ufal/atrium-keyword-extractor`

LLM-enrich repo functionality related to keyword extraction should be moved to the new repo 

NLP-enrich repo should cover only LINDAT service calls for textual inputs


Agreed at the AMČR meeting on 30 September: both kinds of keywords move to one new repository, **`ufal/atrium-keyword-extractor`**, which runs one service, `/extract_keywords`.

- **Statistical keywords:** KER, YAKE and KeyBERT from this repository's `keywords.py`. KeyBERT is the default, YAKE selectable, and every keyword carries its method and score.
- **Controlled keywords:** the LLM over the AMČR and TEATER vocabularies, plus the entity links to AMČR and AAT, from ufal/atrium-llm-enrich (its `/extract_keywords` today).
- **nlp-enrich** keeps only the LINDAT calls (UDPipe, NameTag) and what is built from them: TEITOK and the record projection.

This also removes the one large duplicated code base between nlp-enrich and llm-enrich (the LLM engine and the vocabulary code, about 360 KB per copy). It moves once instead of being kept in two places.

**Scope**
- create the repository from the history of both sources, so `git log --follow` works for the moved files
- one service, `/extract_keywords` (`kind=statistical|controlled|both`), reading the record after nlp-enrich, with the same typed contract, limits and health checks as the other services and a `CreateAction` in its response (atrium-project#71)
- in the record: the new `keywords` block (atrium-project#73) owned by keyword-extractor; `enrichment` and `entities[].pid` taken over from llm-enrich as its successor
- the vocabulary build moves there too and is published as a versioned release asset (CC0), for the translator and the E2E
- nlp-enrich without `keywords.py`, the `llm` stage, `kw_method`/`num_keywords` and the KeyBERT/YAKE dependencies. That makes it a CPU-only image. The parameters are deprecated in 0.23.0 and removed in 1.0.0.

**Acceptance**
- [x] `ufal/atrium-keyword-extractor` exists with the history of the moved files
- [ ] there is one copy of the LLM and vocabulary code in the ecosystem
- [ ] `/extract_keywords` returns a record with `keywords` (method and score on each keyword) and `enrichment`
- [x] nlp-enrich's image has no torch, and its spec has no keyword parameters
- [ ] the hub E2E is green with the new keyword step

**Out of scope:** custom NER and its annotation tooling (#7, ufal/atrium-nlp-enrich#18), which stay here; the born-digital converter (ufal/atrium-digital-convert#1).

Plan: `agent_dev_logs/plans/40.plan.md`.
