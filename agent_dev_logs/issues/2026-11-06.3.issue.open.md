This is Option 4 of #2, as proposed there on 11-06. It is part of ufal/atrium-page-classification#58 (overview: ufal/atrium-project#83). A decision model picks a term by walking down the vocabulary: facet, then group, then the terms' own tree, with "none of these" at every step. It covers the category and the meta-text decision only. Keywords stay as they are.

## Scope

1. **`dm_run.py`** (no torch) reads the same lines as the LLM runs, with the same functions: `llm_client_shared.read_input_rows()`, `should_process_line()`, the two-line context window, `excluded_prompt_themes()` and the geographic guardrail.
2. **The descent for each line:**
   - the steps are: meta-text (yes/no), then the facet, then the geographic gate (where the guardrail covers the branch), then the group, then the children;
   - at each level the children are offered, plus `<this term>` where the node is itself a term, plus `none_of_these`;
   - a beam keeps up to 3 children with p ≥ 0.2. The answer is the best path that ends in a term; if no path does, the line is unresolved;
   - the one node with more than 255 children (`historické oblasti a státní útvary`) is split into ordered chunks.
3. **The tree** is generated from `vocabulary_terms()` and `data_samples/vocab/specificity_pairs.csv` (`dm_run.py --dump-tree`). Its digest and the vocabulary version go into each run's paradata.
4. **Runs** on the 19 documents (1,029 lines kept by the quality filter):
   - **models:** Clef first, on Pavel's internal endpoint, then Clef-Flash and Strands Decider 2B;
   - **ablations:** beam 1 against beam 3; no context against two lines of context; guided descent (candidate terms ranked first).
5. **Output** in the shape of the LLM runs (`KW_PER_DOC_DM_<model>/`), plus a `decision` object: the path, the probabilities at each level, unresolved, lane, status, requests and latency.

## Acceptance criteria

- [ ] `decision_client.py` is copied from page-classification and pinned in `tests/test_vendored_decision_parity.py`.
- [ ] The tree is generated, never written by hand, and its digest is recorded.
- [ ] The line-mode runs of each served model are scored with `score_categories.py` beside the R3 runs.
- [ ] `score_categories.py` counts a null category as unresolved, not as missing, with tests.
- [ ] Forced labels (the watch list of 10-16) are 0, or explained.
- [ ] Reported against R3: the unresolved share, the level where the descent stops, and the requests, latency and input tokens per line.
- [ ] The ablations are recorded.
- [ ] Each run records where the lines were sent, as agreed on ufal/atrium-project#83.
- [ ] Once `gold_workbook.csv` has gold labels, these are posted on #2:
  - D1 scores and calibration per facet;
  - the D2 comparison with the constrained prompt and Option 3.

## Boundaries

- No change to the service, the prompt, `MODEL_KEY`, the defaults or the record during the pilot.
- No keyword (span) extraction.
- Facets and groups are used for routing only, never as a category (P1, P2).
- No hosted inference on archive text.

For each line, the model will receive the line, marked within two lines of context on each side, and answer a sequence of questions. Each question lists options, and the model returns a probability for each one, so it can only answer with a listed option. Apart from the option names, the model is told only one short description per option. These descriptions are generated from the vocabulary and the prompt:

- **Content or not** (yes/no): "Is the marked line archaeological content?" The "no" option is described by the prompt's meta-text rule (the paragraph starting "CRITICAL: If the marked line is purely administrative…"), and "no" gives `Nerelevantní (meta-text)`.
- **Facet** (10 options, plus "none of these"): a facet is described only by its group titles. For example, Material reads "groups: materiál objektu/předmětu; specifikace objektu; specifikace předmětu; způsob provedení (objekty)".
- **Place, people or dynasty** (yes/no): asked before the countries, peoples, historical regions and dynasties are offered.
- **Group:** a group is described by its first six terms in Czech alphabetical order. Where a group's only top-level term has the group's own name, the description just repeats it: "for example: materiál objektu/předmětu".
- **Terms, level by level:** each Czech term is described by its English label. Two more options are always there: "this term itself", to stop at a broader term, and "none of these", which leaves the line unresolved.

The tree comes from [dm_run.py](https://github.com/ufal/atrium-keyword-extract/blob/test/dm_run.py) (`python3 dm_run.py --dump-tree tree.json`).

1. **Wording:** do these descriptions tell the facets and groups apart well enough, or should some of them get a sentence of their own? The meta-text rule was written as an instruction for the generative prompt; does it work as the description of "not archaeological content"?
2. **Gold:** `gold_workbook.csv` has 2,172 lines, none of them labelled yet. Is anyone set to label them? If not, could the 384 lines that already have candidate terms be a first batch?

**Decision models, briefly.** A decision model is a language model that chooses instead of writing. It gets an input (a page image, a text, or both) and questions whose answers are fixed in advance: yes/no, one option from a list, or a point on a scale. It returns a probability for every allowed answer, so it never answers off the list, though it can choose wrongly. It is not trained on our data: a short task description, the question and one line per answer are all it is told. One pass answers dozens of questions, so it is cheap, and the probabilities mark the cases it is unsure of, which a person or the existing tool can then decide.

The vocabulary has 4,711 terms, but one question can offer at most 255 answers, so the model walks down the tree one short question at a time and may stop at "none of these". The line-by-line walk is still being written; the document type is ready.

Measured:
- **Terms:** as the description sets out, once the walk runs.
- **Document type:** against the catalogue types, with how often it answers "unspecified", and a second score over only the documents whose catalogue type is a written one, since photographs, plans and drawings are not offered.
