### B — Controlled kind in `POST /extract_keywords` — 🟢 built in the 2026-10-07 change set
- A client of an inference service (`LLM_BACKEND`: OpenRouter or Ollama); no weights in the `-api` image. Built at startup when configured; `/info` `controlled` says what runs or why not.
- Line mode over the record's lines, on the prompt `llm_run.py` sends; one call per qualifying line.
- `kind=statistical` is independent of it; `kind=both` reports a controlled kind that is not configured (`skipped`) or fails (`failed`) without losing the statistical keywords.
- Results go to the record's `enrichment` block (and `entities[].pid`) through the one record writer and its Layer D gate; never into the statistical list.
- `.github/production-image.json` gained exactly the five files the entrypoint now reaches.
- **Still gated on #2's D1 evaluation** before anyone reads the output as quality.

### C — The record (with atrium-project#73)
- The additive `keywords` block (statistical, document + per page, `method`/`score`/`rank`), owned by `keyword-extract`, added in the next hub schema round.
- This service then writes it.
- nlp-enrich's TEITOK projection reads it: `api_util/teitok_project.py` still names `app-llm-enrich` / `app-kw`.

### D — Vocabulary artefact (with atrium-project#72)
- Publish the CC0 vocabulary (`union_nested.json`, flat files, `union.skos.ttl`, `*.meta.json`) as a release asset with a checksum.
- The hub E2E and the translator read it instead of rebuilding.

### E — Release
Push the change set and tag the next release with V-6 (`6a6619d`) and the controlled kind. The spec change is additive: `atrium_openapi.py compare` with the pinned oasdiff (v1.32.1) reports no breaking change against `v1.0.0-beta`.

### F — Hub E2E, the controlled step
The keyword step runs the `-api` image with no backend. A controlled assertion (`kinds[controlled].status == "ok"`, an `enrichment` block in the returned record) needs an `OPENROUTER_API_KEY` secret and a model id in the hub, or an Ollama service in the runner.
