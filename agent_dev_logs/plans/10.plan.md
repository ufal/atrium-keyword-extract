## Context
Non-tabular documents are converted by flexiconv straight to TEITOK XML, and keyword extraction / LLM
enrichment read the resulting `.teitok.xml` through the stdlib `teitok_read`. The first real conversions with
the pinned flexiconv `v0.3.10` (2026-09-23) showed that flexiconv's TEITOK is **not sentence-segmented** —
plain formats give `<p>` text, layout formats (PAGE XML, hOCR, ALTO) give `<tok bbox>` inside `<div>`/`<lb/>` —
while `teitok_read` only understood `<s>`, so every converted document contributed **zero rows**. The adapter
also called a non-existent library function, let the CLI `pip install` extras mid-run, collided on shared
stems, and wrote into the directory the stage-4 XSD gate owns. Rounds 2 and 3 fixed all of it and added the
annotated path; everything is released in v0.21.0.

## Strategic actions

### A — Make converted documents readable ✅ (round 2)
1. `api_util/teitok_read.py` (single canonical copy; llm-enrich re-vendors it verbatim, pinned by SHA-256 in its
   `tests/test_vendored_teitok_parity.py`): rows `<s>` (prefer `@text`) → else `<lb/>`-delimited lines when the
   document has `<tok>` → else leaf blocks (`p head item cell l u ab quote`), page from `<pb>`; tokens with
   text-faithful spacing; `<dtok>` text ignored; `upos` = `@upos` or `@pos`; untokenized documents → whitespace
   split with empty `lemma`/`upos`; `</n>` repair; `sentence_text()` helper.
2. Fixtures captured from real `v0.3.10` output under `tests/fixtures/teitok/flexiconv/` + tests. Caveat kept in the
   README: the legacy KER method needs lemmas.

### B — Fix the adapter and the conversion step ✅ (round 2)
3. `api_util/flexiconv_convert.py`: library `run_convert`, CLI fallback with `--no-auto-install`, timeout, typed
   errors, one-line `[FAIL]`, exit codes.
4. Output layout `TEITOK_FLEXICONV_DIR`; `<stem>.teitok.xml` / `<stem>.<ext>.teitok.xml`; `FLEXICONV_FORCE`.
5. `requirements_flexiconv.txt` extras pin.
6. `config_api.txt` (`FLEXICONV_FORMATS` += `xml hocr`, `TEITOK_FLEXICONV_DIR`, `FLEXICONV_FORCE`); `api_flexiconv.sh`
   paradata + core gate.
7. `para_config.txt`: `flexiconv = GPL-3.0 ; conditional ; …` (the comment records the declared GPL-3.0-or-later).
8. ✅ (round 3) `run_pipeline.py --with-flexiconv`: `api_flexiconv.sh` runs as the first stage and
   `FLEXICONV_ANNOTATE=true` is set for every stage.
9. ✅ [#38](38.plan.md) action E (implemented 2026-09-24, on `test` since `8003051`): a missing flexiconv stops the stage
   (exit 3), a failed conversion makes it exit 1 after the rest are converted, and `--start-from` any stage skips
   the conversion. Needed before the close-out run below.

### C — Real-document experiment (the 08-02 task; ~~close-out gate~~ optional since 2026-09-26)
10. ✅ Reference inputs and run (flexiconv's own examples): 6/6 converted, `--profile core` 6/6, YAKE keywords for

11. ✅ `api_util/flexiconv_report.py "$TEITOK_FLEXICONV_DIR" --inputs "$INPUT_DOCS_DIR"` prints the table (input +
    format, pages, rows, tokens, elements with bbox, `--profile core` verdict, unconverted inputs; exit 0 only if
    every document passes). ⏳ Run it on ≥1 real ATRIUM document per format (user) and paste it into the README.

### D — Annotation of converted documents ✅ → [#38](38.plan.md)
12. `FLEXICONV_ANNOTATE=true`: stage 1 reads the converted file's rows, stages 2–3 are unchanged, stage 4 takes
    the layout from the converted file (`api_util/teitok_layout.py`, `summarize_nt_udp.layout_source()`), and the
    writer emits TEITOK format 2. Released in v0.21.0. Round 4 found page provenance, identity, gate and service
    gaps; they are #38's actions A–F.
