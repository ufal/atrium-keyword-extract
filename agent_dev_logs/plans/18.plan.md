## Context

Issue #7 locks the design for a **domain-specific archaeological NER model** trained on **NameTag 3** with a flat `archaeo` tagset of six types — **ARTEFACT, PERIOD, LOCATION, CONTEXT, MATERIAL, SPECIES**. The next unstarted step is **building training data**, whose intended flow is **LLM pre-annotate → human correction by archaeologists → export gold IOB2**. Issue #18 is the open sub-task: *"Pick one or create one tool for fast annotation of texts with new NE types"*.

The planning docs (`agent_dev_logs/plans/7.plan.md`) had **defaulted to BRAT for the correction step but never compared alternatives**. This plan evaluates the candidates (INCEpTION, doccano, Label Studio, BRAT) and provides the architectural integration pieces (data converters, docker configurations). **The final tool choice is currently pending stakeholder consensus, so all viable options are being kept on the table.** 

### Hard requirements the tool must satisfy (from #7 + repo conventions)
- **Fast** annotation — the real speed lever is **model/LLM pre-annotation the annotator only corrects**, not labelling from scratch.
- Ingest **LLM pre-annotations** (their `llm_utils.py` stack already emits constrained JSON).
- Export to **NameTag 3 IOB2**: UTF-8, **two tab-separated columns** `token⇥label`, blank line between sentences, `-DOCSTART-→O`, **`|`-joined labels** for overlaps (e.g. `bronze → B-MATERIAL|B-ARTEFACT`). This is exactly what `api_util/call_nametag.py::_get_ne_suffix()` already parses.
- **Czech** first (then Dutch/English), Unicode-safe, plus **Latin** taxonomic terms.
- **Multiple archaeologist annotators** (domain experts, likely non-technical) → simple UI.
- Self-hosted, **open-source**, Docker.
- Deviation cost matters: the project runs **no DB and no auth anywhere** by deliberate design; any tool with its own DB/auth is the first stateful service and must be flagged to the orchestration owner (`rharasim`, ARÚB).

## Deployment scope: standalone campaign

Regardless of the final tool selected, it will be run via its **own docker-compose** on a UFAL/ARÚP server or workstation, used only for the annotation campaign. The **schema config + converters live in `atrium-nlp-enrich`** (not a new productionised repo). Nothing is added to the runtime pipeline; the tool's only contract with the pipeline is the exported IOB2 files.

## Common setup — tool-agnostic (do this regardless of tool)

1. **Freeze the `archaeo` label scheme** as a shared config file in the repo: the 6 types + the boundary guidelines already written in `agent_dev_logs/issues/2026-05-11.7.issue.open.md`. This doubles as the annotator guideline handout.
2. **Prepare input** from Czech text lines (`data_samples/DOC_LINE_CATEG/*.csv`, `text` column) → sentence/token-segmented **CoNLL-U** via the existing `api_util/call_udpipe.py`. Tokenisation is fixed here so IOB2 export is token-exact.
3. **Generate LLM pre-annotations** with the existing stack: ~~reuse `llm_run.py::build_schema()/build_system_prompt()` and `llm_utils.py::read_input_rows()/get_context_window()`~~ _(2026-09-26: through llm-enrich's engine and client, #67 R7)_. Target ~10 sentences/type for the demo, scale toward ~10k entities/type.
4. **Two small converters** (new, under `atrium-nlp-enrich/annotation/`), the only real code to write:
   - `conllu_to_<tool>`: LLM-JSON (+ CoNLL-U tokens) → the tool's import format.
   - `<tool>_export_to_iob2`: tool export → NameTag IOB2. Validate/normalise with NameTag 3's `preprocessing/iob_to_iob2.py`.
5. **Extend downstream mappings**: add archaeo entries to `api_util/summarize_nt_udp.py` (`CNEC_TYPE_MAP`/`get_ne_explanation()`), and the TEITOK `@type` interop (`LOCATION→LOC`, rest→`MISC`).

## Next Steps: Finalizing the Tool

The team needs to test the provided configurations and reach a consensus:
*   **Label Studio**: Quick configuration and straightforward UI (on `test` under `annotation/` since 2026-09-07).
*   **Doccano**: The lightest to stand up; keyboard-driven flat NER. 
*   **INCEpTION**: If model-in-the-loop active learning + multi-annotator curation/IAA + native nested spans become worth the heavier setup (adds a DB + auth → first stateful service; flag to `rharasim`).

## Verification (end-to-end, on a tiny sample before scaling)
1. `docker compose up -d` the chosen tool; confirm the web UI loads and the archaeo project/labels exist.
2. Run one `data_samples` Czech doc through `call_udpipe.py` → CoNLL-U → LLM pre-annotation → import; confirm suggestions appear in the UI.
3. Hand-correct ~10 sentences covering all 6 types; export; run the specific `<tool>_to_iob2.py` export script.
4. **Validate the IOB2**: exactly two tab-separated columns, blank lines between sentences, `-DOCSTART-→O`, pipe-joined overlaps; round-trip through NameTag's `preprocessing/iob_to_iob2.py` with no errors; confirm `api_util/call_nametag.py::_get_ne_suffix()` parses the multi-labels.
5. Smoke-test consumption: a NameTag 3 training dry-run on the tiny set (or at minimum tagset-registration in `nametag3_dataset.py`'s `TAGSETS`) to prove the file is training-ready — closing the loop into #7 Phase 1.
