# The one three-way switch, because the decision has three states rather than two
# (issue #6, C1 / M11 / M12):
#   strict      — "NEVER select a country/language/region name" (pairs with the
#                 geographic TEATER branches being excluded)
#   preference  — "select one only when the line is genuinely about it" (pairs with
#                 those branches reinstated)
#   off         — no geographic rule at all
# taxonomy_config.json's `geo_guardrail.active` must agree: vocab_build.py renders this
# prompt and refuses to build a vocabulary that contradicts it.
PROMPT_GEO_GUARDRAIL=preference

# How the term list is laid out under "THEMATIC VOCABULARY:" — the same terms in the same
# order, under three amounts of structure. @motyc (issue #6, M2) asked to separate "which
# terms are available to the model" from "how those terms are grouped for inference", and
# to check empirically how much the grouping affects results now that the whole
# vocabulary fits a 128k window. This flag is that experiment's only moving part:
#   facet_sub — "--- Facet / Subgroup ---", both curated levels (the shipped prompt)
#   facet     — "--- Facet ---" only, without the source's own second level
#   flat      — no headers at all
# All three offer the same terms and truncate identically; `facet_sub` additionally makes
# each facet's sub-groups contiguous. So `facet` vs `flat` measures the headers alone, and
# `facet_sub` vs `facet` measures the source's second level.
PROMPT_VOCAB_GROUPING=facet_sub

# =============================================================================
# Transformers backend: chunked prefill
# =============================================================================
# The whole prompt is 58 260 tokens with Qwen3.6's tokenizer. Prefilled in one pass, a
# single layer's activations outgrow what a 24 GB card has left beside the weights (OOM on
# every line, Qwen3.6-27B on 2x A30, 2026-10-12). In chunks of this many tokens the peak
# stays bounded, and the cache carries the state from chunk to chunk, so the computation is
# the same. 0 = one pass. vLLM chunks its prefill by itself and ignores this.
PREFILL_CHUNK_SIZE=8192

# Required for llama4-maverick (1 M token native window causes OOM otherwise).

# window the engine serves: the whole prompt — 4 711 terms and the instructions — is

# Activity Area, Feature, the start of Artefact) reach the model, and the run's
# paradata records the cut as a `vocab_prompt_budget_tokens` note. For a run over the
# whole vocabulary set 65536, and size the KV cache / CPU offload for it.
